# Отчёт: Link Tracker - Соответствие 12-факторной методологии

## Доменная область

Link Tracker - веб-приложение для отслеживания обновлений ссылок на GitHub и StackOverflow. Пользователи добавляют интересующие ссылки через Telegram бота (фронтенд), система автоматически проверяет обновления и отправляет уведомления.

## Стек

- **Backend**: Java 21, Spring Boot 3.4.1, REST API
- **Database**: PostgreSQL 16, Spring Data JPA/JDBC, Liquibase
- **Frontend**: Telegram Bot API (внешний клиент)
- **Build**: Maven 3.9.11
- **Deployment**: Docker Compose

## Сущности

### Chat
Зарегистрированный пользователь Telegram.
- `id` - Telegram chat ID
- `registered_at` - дата регистрации

### Link
Отслеживаемая ссылка.
- `id`, `url`
- `last_check_time`, `last_update_time`
- `created_at`

### Tag
Категория для ссылок.
- `id`, `name`

**Связи**: Many-to-Many между Chat↔Link и Link↔Tag через junction tables.

## Соответствие 12 факторам

### I. Codebase ✅
Одна кодовая база в Git (https://github.com/Celine887/Java, ветка `sre`). Возможны разные развертывания (dev, prod) с одной базой.

### II. Dependencies ✅
Все зависимости явно объявлены в `pom.xml`. Maven обеспечивает воспроизводимую сборку.

### III. Config ✅
Конфигурация через переменные окружения в `application.yaml`:
```yaml
spring:
  datasource:
    url: ${SPRING_DATASOURCE_URL:jdbc:postgresql://localhost:5432/link_tracker}
    username: ${SPRING_DATASOURCE_USERNAME:postgres}
    password: ${SPRING_DATASOURCE_PASSWORD:postgres}
```

Файл `.env` для локальной разработки (в `.gitignore`).

### IV. Backing Services ✅
PostgreSQL подключается через JDBC URL - легко заменить на другой экземпляр. GitHub/StackOverflow API - внешние HTTP сервисы.

### V. Build, Release, Run ✅
- **Build**: `mvn clean package` → `scrapper-0.0.1.jar`
- **Release**: Контейнеризация с конфигурацией
- **Run**: `java -jar scrapper.jar` или Docker

Стадии четко разделены.

### VI. Processes ✅
Stateless процесс. Все состояние в PostgreSQL. Возможно горизонтальное масштабирование без sticky sessions.

### VII. Port Binding ✅
Встроенный Tomcat. Приложение самодостаточно:
```yaml
server:
  port: ${SERVER_PORT:8080}
```

### VIII. Concurrency ✅
Гориз онтальное масштабирование через запуск нескольких инстансов. Stateless архитектура позволяет добавлять процессы динамически.

### IX. Disposability ✅
Быстрый запуск (~10-15 сек). Graceful shutdown с таймаутом:
```yaml
spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s
server:
  shutdown: graceful
```

### X. Dev/Prod Parity ✅
Одинаковые технологии и версии PostgreSQL 16 в dev/prod. Docker Compose обеспечивает воспроизводимость.

### XI. Logs ✅
Логи в `stdout`/`stderr`:
```yaml
logging:
  level:
    root: INFO
```
Агрегация - ответственность окружения (Docker, Kubernetes).

### XII. Admin Processes ✅
Миграции БД через Liquibase (автоматически или вручную через `mvn liquibase:update`). SQL скрипты для административных задач.

## Итог

**Приложение полностью соответствует 12-факторной методологии** - готово к cloud deployment и горизонтальному масштабированию.
