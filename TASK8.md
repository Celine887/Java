Цель
Вы уже реализовали Bot Service и Scrapper Service, в нашей целевой архитектуре также предполагается AI Agent Service, который должен выполнять интеллектуальную обработку данных. Обе части ДЗ реализуются внутри одного сервиса AI Agent Service. Часть 1: чтение + фильтрация + суммаризация, часть 2: приоритизация + группировка + отправка. 

В этом домашнем задании вам будет необходимо реализовать часть этого сервиса, а именно - получение сообщений из Kafka, фильтрацию и суммаризацию.

AI Agent Service:

Получает обновления из Kafka

Фильтрация по стоп-словам и авторам

Суммаризация длинных обновлений

Работает как промежуточное звено между Scrapper и Bot

В рамках этого ДЗ:

Основная бизнес-логика Bot и Scrapper не изменяется

Допускается внесение минимальных изменений в интеграционный слой Scrapper/Bot, необходимых для передачи и чтения новых полей Kafka-сообщений в рамках взаимодействия с AI Agent Service

Реализовать необходимо только функциональность AI Agent Service; изменения в других сервисах должны быть ограничены интеграцией с новым контрактом

Что нужно сделать в этом ДЗ
Создать новый модуль/сервис AI Agent Service с Kafka consumer, читающим из топика link.raw-updates.
Реализовать фильтрацию входящих обновлений:
по стоп-словам пользователя,

по списку исключённых авторов,

по минимальной длине текста.

Реализовать суммаризацию - если текст обновления превышает настраиваемый порог, сократить его (через AI API или заглушку).
Покрыть логику unit и integration тестами согласно описанным сценариям.

Пользовательские настройки
Настройки фильтрации и суммаризации задаются в файле конфигурации AI Agent Service.

Пример конфигурации:

ai-agent:
  filtering:
    stop-words:
      - spam
      - ads
      - promo
    excluded-authors:
      - bot-user
    min-length: 20
  summarization:
    threshold: 500

stop-words - список стоп-слов. Если текст обновления содержит хотя бы одно - обновление отфильтровывается.

excluded-authors - список исключённых авторов. Если автор обновления в списке - обновление отфильтровывается.

min-length - минимальная длина текста. Обновления короче - отфильтровываются.

threshold - Порог суммаризации. Если длина текста превышает значение - текст суммаризируется.

Пример контракта сообщений Kafka
Входной топик: link.raw-updates
{
"id": 12345,
"description": "Полный текст обновления...",
"author": "username",
"tgChatIds": [111, 222]
}

Выходной топик: link.processed-updates
{
  "id": 12345,
  "description": "Обработанный (возможно суммаризированный) текст",
  "tgChatIds": [111, 222],
  "priority": "HIGH" (приоритезация будет реализована в следующем дз)
}

Поведение суммаризации
Суммаризация применяется после фильтрации, к тексту обновления, если его длина превышает summarization.threshold.

Варианты:

Заглушка. Обрезать текст до threshold символов и добавить "...".
AI API (например, Hugging Face Inference API, YandexGPT trial). Текст передаётся с промптом вида "Summarize the following update in 2–3 sentences".
Суммаризация-заглушка и суммаризация через AI API - взаимоисключающие варианты. Выбирается один.

Сценарии тестирования
FR-1: Получение сообщений из Kafka
TC-1.1 Получение события из link.raw-updates
Условие:
Scrapper Service публикует корректное сообщение в Kafka topic link.raw-updates.

Ожидаемый результат:

AI Agent получает сообщение

Сообщение передаётся в обработку

Ошибок десериализации не возникает

TC-1.2 Некорректный формат сообщения
Условие:
В topic публикуется сообщение с некорректной структурой.

Ожидаемый результат:

Сообщение не приводит к падению сервиса

Ошибка логируется

FR-2–FR-4: Фильтрация
TC-2.1 Фильтрация по стоп-словам
Условие:
Текст обновления содержит стоп-слово из конфигурации.

Ожидаемый результат:

Обновление игнорируется

Сообщение не публикуется в link.processed-updates

TC-2.2 Фильтрация по автору
Условие:
Автор обновления входит в список исключённых авторов из конфигурации.

Ожидаемый результат:

Обновление игнорируется

Сообщение не публикуется

TC-2.3 Фильтрация по минимальной длине
Условие:
Длина текста обновления меньше установленного значения min-length.

Ожидаемый результат:

Обновление игнорируется

Сообщение не публикуется

TC-2.4 Обновление проходит фильтрацию
Условие:
Обновление не содержит стоп-слов, автор не исключён, длина достаточная.

Ожидаемый результат:

Обновление передаётся на следующий этап обработки

FR-5: Суммаризация
TC-3.1 Суммаризация длинного текста
Условие:
Длина текста превышает установленный порог для суммаризации.

Ожидаемый результат:

Выполняется суммаризация

Возвращается сокращённый текст

Исходный текст не передаётся полностью

TC-3.2 Короткий текст
Условие:
Длина текста меньше порога суммаризации.

Ожидаемый результат:

Суммаризация не выполняется

Текст передаётся без изменений
